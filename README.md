# Вечерняя уценка кулинарии 20:00

Локальный инструмент для автоматизации вечерней уценки продукции собственного производства. Он берет срез остатков 1С на 19:30, применяет регламент сети, разделяет бизнес-решение и техническую готовность, рассчитывает цены и формирует два пользовательских артефакта: рабочий Excel и печатный лист.

## Быстрый запуск

На Windows основной сценарий — двойной клик по `Start_App.vbs`.

Приложение запускается через `pythonw/pyw`, поэтому CMD не показывается. Пользователь выбирает `.xlsx`, нажимает **«Рассчитать уценку»**, после чего видит KPI и может открыть итоговый отчет или лист для печати.

Если `.vbs` запрещен корпоративной политикой:

```bash
python app.py
```

## Что делает pipeline

`1С → загрузка → валидация → бизнес-правила → цена → KPI → итоговый Excel → печатный лист`

AI не участвует в runtime. Все решения воспроизводимы и определяются кодом.

### BUSINESS_STATUS

- `AUTO_DISCOUNT`
- `BLOCK_CATEGORY`
- `BLOCK_EXPIRY`
- `BLOCK_BRAK`
- `MARGIN_ALERT`

### EXECUTION_STATUS

- `READY`
- `DATA_QUALITY_REVIEW`
- `NOT_APPLICABLE`

На пользовательских листах внутренние коды заменены понятными формулировками: «Готово к уценке», «Нужно решение директора», «Нужно исправить данные» и т. п.

## Итоговый Excel

После запуска приложение формирует в `output/` два рабочих файла:
- `Итоги_Вечерней_Уценки_20_00.xlsx`;
- `Лист_для_стикеров_20_00.xlsx`.

В Windows-safe архиве заранее приложены их ASCII-копии `output/result.xlsx` и `output/print_sheet.xlsx`, чтобы имена не ломались при распаковке некоторыми архиваторами.

Листы:

1. `01_Директор` — что делать сегодня и ключевая экономика.
2. `02_План_уценки` — только позиции, которые можно брать в работу.
3. `03_Исключения` — причина, действие, ответственный и признак «Стикер?».
4. `04_Контроль_данных` — служебная диагностика мастер-данных.

Готовая копия для проверки без запуска лежит в `output/result.xlsx`.

## Печатный лист

`output/print_sheet.xlsx` содержит карточки только по `AUTO_DISCOUNT + READY`.

Карточка показывает:
- товар;
- номер существующего штрихкода из 1С;
- старую и новую цену;
- остаток;
- срок продажи;
- код 1С.

Новый графический barcode намеренно не генерируется: ТЗ не задает символогию, принтер, размер этикетки, кассовый PLU и число контейнеров. Одна карточка = одна товарная позиция, а не одна физическая упаковка.

## Ключевые правила

- стандартная скидка: −30%;
- Margin Guardrail: цена не ниже `Себестоимость × 1.05`;
- весовой бракераж: `< 0.5 кг`;
- поштучный бракераж: `< 1 шт`;
- срок годности к 20:00 включительно → не участвует в вечерней уценке;
- деньги считаются через `Decimal`;
- округление цены: вниз до 5 ₸ как явно зафиксированное допущение;
- scientific notation штрихкода не восстанавливается;
- пробелы по краям безопасно удаляются с сохранением исходного значения.
